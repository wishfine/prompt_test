# 初中物理 GLM-5.2 匿名双裁判实验方案

## 1. 实验目的

冻结首轮 Prompt 与后处理逻辑，不重新调用首轮模型。复用同一批 497 道教师复核题的三次 Lite 独立结果，只对三次结果不一致的题调用 `glm-5.2`，检验多次 API 是否能把严格准确率从约 85% 提升到 90% 左右。

本实验不复用此前失败的“带着首轮答案找错”二审方式。裁判看不到三次运行身份、票数、多数结果和首轮理由，只看到：

- 当前题干、选项、小问和官方解析；
- 三次结果所形成的两个相邻候选档；
- 该相邻边界的明确标准；
- 两档数量相等、排除当前题的真实教师校准样例。

## 3. 双裁判流程

1. 三次 Lite 结果一致：直接保留，不调用 API。
2. 三次 Lite 结果不一致：
   - 裁判甲从“上档最低门槛是否满足”角度判断；
   - 裁判乙从“下档是否足以解释整题”角度判断；
   - 两者使用同一个 `glm-5.2`，但采用对称角色提示词并发调用。
3. 两名裁判选择一致：直接采用。
4. 两名裁判选择不一致或仅一份结果有效：再调用一次 `glm-5.2` 匿名仲裁。
5. 调用失败、JSON 无效或最终无法形成合法二选一结论：回退三次 Lite 多数票。

所有 API 决策只允许在已知两个相邻候选之间二选一，最多改变多数票一档。

## 4. 防偏设计

- 裁判输入不包含 `run_predictions`、票数、多数档或“首轮等级”。
- 两档 few-shot 数量严格相等，当前题不能成为自己的 few-shot。
- few-shot 按题型、信息载体、实验/图表要求、状态数等结构相似度动态选择。
- 裁判必须依据当前题原文和官方解析，不允许靠“题干长、关键词高级、像压轴题”等外观判断。
- `glm-5.2` 默认不发送 temperature；只有显式设置 `--temperature` 时才发送，避免网关参数兼容问题。
- 输出保留每次调用、模型、用量、耗时、结论来源和错误信息，可完整审计和断点续跑。

## 5. 运行命令

```bash
cd ~/prompt_test
git pull --ff-only origin main
source venv/bin/activate

mkdir -p outputs/model_runs outputs/logs outputs/plots/glm52_dual_judge_497

nohup python -u src/physics_difficulty_disagreement_judge.py \
  --run outputs/model_runs/lite_physics_teacherfeedback_497_run1.jsonl \
  --run outputs/model_runs/lite_physics_teacherfeedback_497_run2.jsonl \
  --run outputs/model_runs/lite_physics_teacherfeedback_497_run3.jsonl \
  --labels data/labeled/physics_review_500_default.jsonl \
  --reference-questions outputs/visualizations/lite_physics_v2_random1000_visualized500.jsonl \
  -o outputs/model_runs/glm52_dual_judge_teacherfeedback_497.jsonl \
  -e outputs/model_runs/glm52_dual_judge_teacherfeedback_497_errors.jsonl \
  -p prompts/初中物理匿名边界裁判提示词.txt \
  --strategy dual \
  --judge-model glm-5.2 \
  --second-judge-model glm-5.2 \
  --arbiter-model glm-5.2 \
  --fewshot-per-level 3 \
  -c 10 -t 180 -r 3 \
  > outputs/logs/glm52_dual_judge_teacherfeedback_497.log 2>&1 &

PID=$!
echo "$PID" | tee outputs/logs/glm52_dual_judge_teacherfeedback_497.pid
```

查看进度：

```bash
tail -f outputs/logs/glm52_dual_judge_teacherfeedback_497.log
```

实验完成后，核心指标位于：

```text
outputs/model_runs/glm52_dual_judge_teacherfeedback_497.jsonl.summary.json
```

生成图表：

```bash
python tools/plot_disagreement_judge_results.py \
  --summary outputs/model_runs/glm52_dual_judge_teacherfeedback_497.jsonl.summary.json \
  --name GLM-5.2双裁判 \
  -o outputs/plots/glm52_dual_judge_497
```

## 6. 验收标准

优先看以下指标：

1. `final_accuracy`：是否接近或超过 90%；
2. `judge_accuracy_on_valid_disagreements`：目标至少 85.83%；
3. `improved_vs_majority`、`worsened_vs_majority` 和 `net_improvement`；
4. 四个相邻边界各自准确率；
5. `dual_judge_agreement_rate` 与 `arbiter_case_count`；
6. 各档 Precision、Recall、F1；
7. API 错误数与 token 用量。

若最终准确率不升、净改对不足或某个边界明显低于多数票，则不进入生产。该实验不会修改冻结首轮 Prompt 和后处理结果。
